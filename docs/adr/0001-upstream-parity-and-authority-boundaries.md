# Preserve upstream outcomes across explicit authority boundaries

DevSpace-Oracle treats published upstream behavior and its user-visible outcome as the default authority. The fork departs only for a reproduced reversible defect or a concrete mechanistic failure at a high-impact authority boundary, and then implements a safer equivalent rather than removing the upstream capability; architectural preference, theoretical concern, and defense-in-depth alone are insufficient divergence evidence.

## Decision

Oracle submission is exact-or-stop. Locale-specific labels may locate controls, but only final visible model and effort evidence authorizes submission: regular GPT uses GPT-5.6 Sol at Extra High/Power 4, Pro uses GPT-5.6 Sol at Pro/Power 5, and Ultra Economy local work requires task-bound Luna/Max runtime proof. The system never silently changes model, effort, backend, or transport.

Every external attempt is durably identified before submission can become possible. Recovery continues only that exact attempt or session; ambiguous submission retains its lock, recovered Web Multi solvers are not resubmitted, and a merger is an exact reserved continuation rather than a replacement. An Oracle CDP disconnect is classified as not executed only by immutable proof defined for that exact tested Oracle version.

DevSpace authority is registration-bound. First initialization exposes the Owner secret only through a human-only private checkpoint; existing configuration is reused, roots are registered additively, removal is an explicit revocation, and registration or reconnect recovery is bounded to the exact failing service and followed by authoritative readback. Pro uses the registered workspace as a read-only adaptive transport by default, while hash-bound attachment transport remains an explicit frozen-evidence mode and is never an automatic fallback.

The shipped platform remains Windows 11 until another platform has a representative installation, runtime, recovery, rollback, and removal proof. Local Multi-GPT remains optional and lazily activated through a registered executable; global native-agent roles require an explicit scoped post-install merge that preserves user model preferences and unmanaged roles. Drive-root hygiene is policy-only and does not authorize broad installer or doctor scans, moves, or deletion.

## Consequences

Each upstream change is classified as adopted, replaced by a safer equivalent, deferred by an explicit product boundary, or rejected with concrete evidence. Guards that only obstruct a supported outcome without preventing a demonstrated harmful scenario are removed rather than accumulated. The shared terms and prohibited aliases for these boundaries live in the repository root `CONTEXT.md`.
